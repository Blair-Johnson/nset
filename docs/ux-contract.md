# UX redesign component contract

The baseline is 65db4ff. The current branch replaces the one-off workbench with experiment/run tables leading into a mixed dashboard. MLflow is the primary navigation/editor reference; W&B supplies the sectioned-workspace reference. Preserve full-history numeric semantics, not the baseline UI.

## Product layout

The app opens an Experiments table. An experiment opens a run table with selection, sortable useful columns and search/status filtering. Experiment-level Runs and Charts views are navigation, not modality tabs. Charts opens a named saved view and shows selected runs, an Add chart action and collapsible namespace sections. Scalar and image cards share the same grid. The default Overview follows selected runs; custom cards can bind explicit run/metric sources anywhere in the database.

Use a light neutral application surface, a restrained blue accent and readable muted text. No raw-derived/canonical/snapshot/authoritative jargon in ordinary UI. Normal screens show names, values and useful actions. Precision caveats live in tooltips or expandable details, not always-visible paragraphs. Per-card loading/errors remain honest and concise.

## Shared types and ownership

`web/src/workspace-types.ts` is parent-owned and defines all integration types. Do not change it independently. Types import the existing ViewConfig; its safe advanced literal schema stays available internally, but no JSON editor is required to use the new app.

Backend worker owns src/api.rs, src/db.rs, src/models.rs and new tests/backend_catalog.rs. State worker owns web/src/workspace.ts, catalog.ts and their unit tests. Navigation worker owns web/src/plot.ts, navigation.ts, options.ts, navigation unit tests and new web/tests/navigation.spec.ts. Cards worker owns web/src/cards.ts, cards.css, images.ts and new card/image-specific tests. Editor worker owns web/src/chart-editor.ts, chart-editor.css and new editor-specific tests. Parent owns main.ts, style.css, shell state, new shared types, obsolete UI removal, end-to-end tests, scripts, README and integration docs. Existing config.ts/math.ts/rendering.ts/matched-path.ts remain unchanged unless an issue requires coordination. Do not edit another worker's files or package/lockfiles.

## Catalog API

Authenticated GET /api/catalog returns Catalog: `{experiments, runs, series}`. A series is a compact record `{run_id,key,kind,count,last_step,last_timestamp,last_value}`. kind is metric or image. Counts retain duplicates; last fields describe the latest inserted observation/frame, not the greatest step. Image last_value is null. Scalar last_value is the latest inserted scalar. Return no full histories or image content and use a consistent read transaction. Include empty runs and experiments. No schema migration is needed. Existing routes and token handling remain unchanged.

## State/data module API

`workspace.ts` exports `seriesId(ref:SeriesRef):string`, `resolveSources(card:ChartSpec, selectedRunIds:string[], catalog:Catalog):ResolvedSeries[]`, `newChart(kind:ChartSpec['kind'], keys:string[], title?:string):ChartSpec`, `defaultSections(catalog:Catalog, runIds:string[]):Section[]`, `newWorkspace(experimentId:string,name:string,selectedRunIds:string[],catalog:Catalog):Workspace`, `validateChart(value:unknown):ChartSpec`, `validateWorkspace(value:unknown):Workspace`, `loadLibrary(storage?:Storage):WorkspaceLibrary`, `saveLibrary(library:WorkspaceLibrary,storage?:Storage):void`, `exportWorkspace(workspace:Workspace):string`, and `importWorkspace(text:string):Workspace`.

Version 2 workspaces are stored under `nset.workspaces.v2`, separate from old settings. `seriesId` uses stable escaped/composite identity, never array position. `resolveSources` filters by kind, expands selected-run keys or explicit references, deduplicates and provides a readable label (run name + metric where needed). Existing but empty series stay discoverable only if actual metadata exists; unavailable explicit references stay in the spec and are reported by the card/editor, not silently rewritten. `newChart` uses readable light-theme colors, 280px plot height, safe defaults, no verbose warnings in normal state. `defaultSections` groups by the prefix before the last slash; slashless keys belong to Overview. Timeseries and images with the same prefix share a section. IDs stable for generated cards/sections; custom cards get unique IDs. Validate bounds/duplicate identities/unsafe keys and never persist credentials or observations. Saved views contain config and references only.

`catalog.ts` exports `fetchCatalog(api:Api,signal?:AbortSignal):Promise<Catalog>` and `MetricStore implements MetricLoader`, constructor `(api:Api,maxConcurrent?:number,maxEntries?:number)`. Default 4 simultaneous full-history loads, deduplicated by run/key, completed cache bounded to 24 entries. Load complete paginated snapshots using Api.metrics; do not downsample. Individual subscriber cancellation must not corrupt another card's request. clear() invalidates/aborts all work on logout/token/server change. A refresh clears the store then refreshes visible cards. Tests must cover stale response/cancellation and queue limits.

## Plot navigation API

Preserve existing PlotPanel constructor `(host,onPick,onWarnings)` and existing render/setPins/reset/clear/destroy. Add `configureInteraction(options:PlotInteraction):void`, `zoom(factor:number,axis?:NavigationAxis):void`, `pan(dx:number,dy:number):void` (fractions of displayed axis spans), `back():void`, `canGoBack():boolean`, and `viewport():{x:[number,number],y:[number,number]}|null`. A factor greater than one zooms in. Configuration can precede first render. The optional controller API owns new behaviors; callers not using it retain legacy fixture behavior until old shell tests are replaced.

Default new-card mode is Pan. Pan drag and Space+drag pan in transformed coordinates (linear/log/asinh); Zoom mode box-selects axes selected by X/Y/Both. Normal wheel scrolls the dashboard; Alt+wheel zooms about pointer, Shift+Alt+wheel may constrain x; never hijack unmodified wheel. Focused plot +/- zoom, arrows pan, 0 fits and Backspace goes back; do not capture input/select/textarea/contenteditable events. Double click fits. Explicit buttons invoke identical methods. Keep a bounded back history. Notify onViewChange; expose bounds for deterministic tests. Fit means configured ranges, not discarded editor settings.

Inspect mode shows/drags A/B vertical lines. Click places the selected A/B cursor; dragging within a small screen-pixel radius of either line moves that line. Threshold mode places/drags a horizontal value cursor. onPin passes data coordinates, not nearest logged points. onHover provides continuous interpolated x for a compact hover readout (null on leave). Avoid simultaneous native drag zoom and custom pan/inspect events. Pins must survive navigation; numerical answers do not change. Resize/zoom rebuild adaptive paths. Preserve nonlinear/reversed-axis correctness and atomic chart rejection. Update default axis/grid colors for the light UI; explicit advanced overrides still win.

## Cards API

`cards.ts` exports `ChartCard`, constructor `(host:HTMLElement,spec:ChartSpec,context:CardContext,actions:CardActions)`, and methods `setContext(context)`, `setSpec(spec)`, `setActive(active:boolean)`, `refresh()`, `destroy()`. Parent places hosts in section grid and controls active=false for collapsed/hidden sections. Cards lazily load near the viewport via IntersectionObserver, cancel stale work, and release resources on destroy. Header has title, maximize and a three-dot menu: Edit chart, Duplicate, size toggle, Move up/down, Remove. Expose data-card-id and data-card-kind; use scoped classes/data-role attributes, no repeated global IDs.

Timeseries cards resolve sources then create synthetic PlotRun.run objects with id=resolved.id and name=resolved.label; this allows multiple metrics from the same run without identity collision. Keep real source IDs in data loaders. The toolbar exposes Pan, Zoom, Inspect, Threshold and concise +/-/Fit/Back controls with tooltips, accessible names and active states; choose X/Y/Both in a compact control. Numeric inspection details expand only in Inspect/Threshold mode. Support A/B active choice, editable coordinate fields, dragging, clear, per-series A/B/delta and expandable all threshold crossings. Continuous hover values may be compact. Use friendly labels (Original/Smoothed, Linear/Smooth interpolation), never raw-derived.

Outliers=robust fits Y to finite 1st/99th percentiles of full analyzed values, without deleting observations or changing readouts. Label clipped display concisely and permit Fit all/Edit to disable it; manual y bounds take precedence. The editor calls this Y auto range: All values / Central 98%, with a short explanatory tooltip. Errors must not present stale data as current. Absent explicit references show a concise unavailable-series message.

ImagePanel keeps existing legacy APIs but adds optional constructor third argument `{compact?:boolean}` and `setSources(sources:ResolvedSeries[]):void` for exact run/key choices. Refactor global IDs, repeated verbose hints and hard-coded canvas size. Keep authenticated bytes, frame races, native pixels and camera preservation. Compact cards have run/key choice only as needed, image canvas, timeline/play/previous/next and concise step caption. Extra rotate/flip/resampling controls can sit in a More menu. Maximize/fullscreen retains timeline. Normal wheel should scroll the dashboard unless intentional image zoom uses a modifier; show a concise tooltip and explicit zoom buttons. Multiple image cards must remain independent. Preserve setActive/destroy semantics.

## Editor API

`chart-editor.ts` exports `openChartEditor(options:{card:ChartSpec,catalog:Catalog,selectedRunIds:string[],onSave:(card:ChartSpec)=>void}):{close:()=>void}`. Use a scoped native dialog with accessible title, Escape/Cancel, focus return and Apply; only persist after successful validation and onSave. No mutation before Apply. The editor has approachable Data, Axes, Appearance sections/tabs (not global modality tabs). Data allows title/type and selected-run metric keys OR explicit searchable cross-experiment/run/metric selection. Image cards select image sources rather than numeric axes. Do not imply unimplemented arbitrary X metric, extra axes or chart types.

Axes exposes step/time, linear/log/asinh, auto/manual min/max, labels/formats and Y auto-range policy. Appearance exposes smoothing with understandable strength/alpha semantics, linear/PCHIP, line/points/area/step styles, grid/legend, size and per-series colors/visibility. Optional More options may expose safe scale direction/base/asinh constant, marker size, line width/dash/opacity, fill and supported presentation fields as actual form controls. Advanced literals loaded from a saved view must be retained unless deliberately edited; simple controls must not appear to work while hidden advanced overrides defeat them. No wall of JSON, no detached settings page. Provide errors next to controls and preserve drafts on failed apply. Short field help only where meaning is not obvious.

## Acceptance and integration

Each worker commits only owned files and returns commit hash, tests run, limitations and integration needs. Use Pixi and recorded rx evidence for substantial tests; shared CARGO_TARGET_DIR may be used only for backend work. Do not edit the running baseline or another worker's worktree. Parent supplies main shell and updates obsolete UI scripts after integration. Screenshots need varied real data and mixed namespaces, not only empty component fixtures. A successful redesign requires complete user journeys and live visual/interaction checks, not only passing old assertions.
