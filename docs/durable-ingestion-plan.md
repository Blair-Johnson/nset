# Durable ingestion and concurrency pass

Base: a45df0f; integration branch feat/durable-ingestion. Main and the preview remain untouched. Implementations use isolated journal, concurrency-config and client-outbox worktrees. Coordinator owns HTTP integration, cross-cutting review, documentation and final testing. No push or merge into main without approval.

## Guarantee and scope

A durable scalar batch is acknowledged only after a FULL-synchronous SQLite incoming-journal transaction commits. Query materialization may lag. A stable batch ID scoped by run makes network retries replay-safe: the same normalized payload returns the existing receipt, different contents return 409. Repeated native observations remain legal. Existing POST metrics, run/experiment mutation and image endpoints keep their existing synchronous semantics; these native endpoints do not themselves implement third-party protocols. The completed extended scope adds a server-side compatibility gateway and TensorBoard collector, described below.

The journal is separate from the query database so materialization does not hold the admission journal's write lock. Query application inserts observations and a durable replay receipt in the SAME query-DB transaction. Only then is the journal entry marked applied and its payload released. A crash between those steps may replay but must not duplicate observations. Journal receipts retain the payload digest and original acceptance metadata; receipt retention is not silently time-limited. Disk exhaustion or capacity limits reject before acknowledgement. No RAM-only acknowledgement or weaker SQLite synchronization.

## Wire contract

PUT /api/runs/{run_id}/ingest/{batch_id} accepts the existing MetricBatch JSON shape, with 1..10000 observations. batch_id is 1..128 ASCII letters, digits, dot, underscore or hyphen. The authenticated, admitted route returns 202 with {"batch_id":string,"run_id":string,"state":"pending"|"applied","accepted":integer,"accepted_at":milliseconds}. A replay returns the original acceptance metadata and current state. GET at the same path returns the receipt with status 200, or 404. GET /api/ingest/status reports backlog count/bytes and a sanitized materialization error if present. No success response implies immediate query visibility; clients may poll the receipt.

Validate run existence and complete metric input before durable acceptance. Digest the normalized typed input, preserving whether timestamps were omitted. Resolve omitted timestamps to the original acceptance time when projecting, never restart/projection time. Serialization of omitted timestamps must be readable by MetricInput's existing non-null deserializer. Store canonical payload bytes and verify them on replay/application. Migration from native schema v1 adds a query-side batch receipt table without losing old data. Reject newer unknown journal/query schemas before persistent changes.

## Internal seams and ownership

Journal worker owns src/ingest.rs, src/db.rs migration/application additions, necessary serializable metric derives in src/models.rs, and dedicated ingest tests. Public interface: cloneable DurableIngest::open(directory, db, IngestOptions) -> Result<Self>; async submit(run_id:String,batch_id:String,batch:MetricBatch) -> Result<IngestReceipt>; async receipt(run_id:String,batch_id:String) -> Result<IngestReceipt>; async status() -> Result<IngestStatus>. IngestOptions fields: queue_capacity:usize (64), max_pending_bytes:u64 (268435456), max_pending_batches:usize (10000), poll_interval_ms:u64 (100), paused:bool (false). A single projector intentionally preserves simple ordering against the single query writer. A paused mode enables backlog maintenance and deterministic restart tests, not an acknowledgement shortcut. Add only `pub mod ingest` to lib.rs if needed for direct tests; coordinator wires AppState/API.

Concurrency worker owns config.rs/main.rs/lib.rs plus ONLY actor capacity/Database opening changes in db.rs. Keep Database::open(directory) and AppState::open(directory,token) as default-preserving wrappers. Add Database::open_with_options(directory, read_workers:usize, queue_capacity:usize). ConcurrencyOptions fields: http_workers, read_workers, db_queue_capacity, write_concurrency, image_concurrency. Defaults: available_parallelism clamped 1..32, 2, 64, 8, 2. Validate bounds (HTTP1..256, readers1..64, DBqueue1..4096, writes1..1024, images1..64) before disk mutation. Config flattens these flags/environment options. AppState::open_with_options(directory,token,&ConcurrencyOptions) configures existing components. Coordinator extends this seam for DurableIngest and its options after integration. Runtime construction moves out of the tokio::main macro to honor http_workers. Do not add multiple SQLite query writers.

Client worker owns python/nset_client/outbox.py, convenience methods/exports in client.py/__init__.py and dedicated client outbox tests. DurableOutbox(client,path,*,max_pending_bytes=268435456,max_pending_batches=10000,workers=1,retry_interval=1.0) persists canonical batches in local SQLite FULL-synchronous storage before enqueue returns. enqueue(run_id,metrics,*,batch_id=None)->batch_id; flush(max_batches=None)->count; pending_count(); start()/close() for optional bounded background delivery. Validate positive bounded options. Persist destination URL identity, but not credentials; refuse reopening an outbox for a different destination. Bound queued payload bytes and count; never drop oldest data. Delete only after a valid matching server receipt. Errors, cancellation and ambiguous acknowledgements retain the same batch ID/payload. Expose last error; do not convert rejection into success. Background workers back off and keep data, close joins workers without discarding pending rows. No blind retries on legacy routes. Client.durable_outbox(path,**options) is an explicit convenience; do not silently change Run.log_batch or add required dependencies.

## Verification and review gates

Test duplicate concurrent PUTs, mismatched-ID conflicts, original timestamps across replay, query transaction rollback, journal capacity, unauthorized/malformed requests, bounded queues, background error visibility, dropped acknowledgements, queued restart recovery and crash between query commit/journal completion. Prove exact per-run values and counts, not just status codes. Exercise outbox offline enqueue, failed send, replay, destination mismatch and close/reopen. Extend native schema tests for v1-to-v2 migration rather than bypassing them. Use process kill/restart tests and disposable data directories; do not touch preview data.

Run native Rust/web/Python regressions, real HTTP durable smoke, and matched throughput workloads with resolved concurrency recorded. Use rx for evidence; workers do not run simultaneous performance loads or share mutable target directories. Journal buffering absorbs bursts but does not establish higher sustained throughput. Report resource, backup and shutdown limitations: pending journal and query DB form one dataset and must be backed up/restored consistently; neither server nor sender can buffer indefinitely on a full disk; actual power-loss durability depends on the filesystem/device honoring sync.

## Extended compatibility implementation

The extended plan is implemented in isolated gateway, MLflow, W&B and TensorBoard worktrees and integrated here. MLflow covers tracking, lifecycle and constrained search with indexed metric identities/latest values. W&B covers the tested official SDK run control, incremental file streams, resume and offline synchronization. TensorBoard preserves original event records and extracts scalars using a replay-safe event-file collector. Unsupported vendor APIs remain explicit errors rather than success responses that discard data; exact exclusions and configuration are in `docs/client-compatibility.md`.

Cross-cutting review covered journal schema/replay identity, outbox shutdown and size limits, gateway origin/auth isolation, bounded upstream IO, directory/backend ownership, chunk-ID collisions, malformed receipts and adapter replay/index publication. Real SDK tests exercise native HTTP, exact scalar readback and explicit artifact rejection, outages and restart. Final gate results belong in `docs/durable-ingestion-evidence.md`; native scalar load probes are distinct from compatibility conformance and are not universal throughput claims.
