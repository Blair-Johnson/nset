# Compact inspection workspace contract

This refinement replaces excess chrome and indirect controls with one coordinated model. Preserve dark tokens, complete-history math and the verified experiment/run/dashboard structure. Do not introduce a new product layout per component. The active request is repeated inspection/selection of dozens of runs while plots stay visible.

## Shared visual rules

Use existing charcoal tokens and typography. Desktop application header is at most 40px high; experiment breadcrumb/name and Runs/Charts controls share one compact row, with no experiment hero heading or repeated name. Workspace tools form one 34–40px row. First namespace header/card should begin within roughly 140px of viewport top at 1440x1000 (target tighter where possible). Tables use 28–34px rows, 5–7px vertical cell padding, no always-visible second metadata line; metadata belongs in selectable columns or run details. All native selects reserve at least 26px on the indicator side; custom summary arrows have a fixed padded slot. Preserve 390px usability without global horizontal overflow.

## Ownership and APIs

Shell worker owns main.ts, style.css, browser-tables.ts, NEW run-drawer.ts/run-drawer.css if useful, workbench.spec.ts and NEW drawer/layout browser tests. Cards worker owns cards.ts/cards.css/plot.ts and card browser tests, plus new resize tests. Navigation worker owns navigation.ts/navigation.test.ts/navigation.spec.ts and a NEW zoom-selection.css imported by navigation.ts. Editor worker owns chart-editor.ts/chart-editor.css/chart-editor.spec.ts and its unit tests. Image worker owns images.ts, NEW image-viewer.css if needed, cards-images.spec.ts and NEW frame-stability tests. Parent owns workspace-types.ts, workspace.ts/state tests, series-colors.ts/tests, scripts, docs and integration. Workers must not change each other's files.

ChartSpec gains optional `layout: {width:number,height:number}` in CSS pixels (card outer dimensions). Parent validates width 300..4096 and height 240..2160; old v2 views without layout remain valid, and legacy size normal/wide stays readable. CardActions gains optional `onDimensions(id,layout): boolean|void`; false means persistence failed and transient size must roll back. Existing onResize remains a compatibility hook, but no new preset-width UI. Geometry-only setSpec changes must not recreate plot/image instances, reset viewport/pins/camera, or reload data. Card root owns desired --card-width and actual height. Shell uses wrapping flex rows: `.chart-grid {display:flex;flex-wrap:wrap;gap:12px;align-items:flex-start}` and `.dashboard-cell {flex:0 1 var(--card-width,calc(50% - 6px));max-width:100%;min-width:min(300px,100%)}`; narrow single-column fallback. Explicit desired dimensions survive viewport clamping and reload. Shell onDimensions persists via existing transactional change().

PlotInteraction gains optional inferZoomAxes. Cards set it true and axis both, remove Navigation axes selector entirely. Navigation's old explicit-axis behavior stays compatible when false/absent. Use about 12 CSS pixels of perpendicular tolerance: clear horizontal drag selects X only; clear vertical selects Y only; diagonal beyond both tolerances selects both. Tiny clicks do nothing. Selection dimensions and released zoom must agree, support reversed/log/asinh axes, preserve pins and history, and cancel cleanly. Overlay uses translucent light blue plus an obvious 1–2px blue border; do not reuse muted gray. Buttons/wheel continue sensible both-axis zoom; Shift+Alt-wheel remains X-only.

## Drawer and shared legend

Charts has a persistent left run drawer (about 260px desktop), independently scrollable, collapsible with an obvious Runs button. It stays open across selection changes and does not require reopening a dropdown. Include compact search/filter, selected count and clear/select matching actions; retain stable checkbox focus and scroll. Dense rows contain a colored swatch, checkbox, short name and compact status if useful; long names truncate with title/full accessible name. Many rows fit without decorative padding. On narrow screens use an explicit overlay drawer, not a 260px squeeze leaving unusable plots.

Use shared `runColor(catalog,runId)` for drawer swatches and `withRunColors(config,sources,catalog)` for card/editor display configs. Colors are stable across selected subsets and missing metric series. These are derived display colors, never persisted as user overrides. Explicit user colors and single-color mode remain authoritative. Multiple metrics from one run share its run color; the optional per-plot legend distinguishes metric keys.

Per-plot legend is collapsed by default; an unobtrusive Show legend control expands an aligned list/table with swatch, run name and metric key, bounded height/scroll, ellipsis and full titles. Do not repeat full run+metric identifiers as a tall wrapped legend on every card. Hover values are a separate bounded readout, not a trailing inline sentence: align name/value rows or show compact count plus expandable detail, keep within card. Explicit A/B/threshold inspector values remain unchanged.

## Direct manipulation

Cards have a real bottom-right drag handle (pointer capture, min/max sizes, cancel and keyboard accessible adjustment) instead of Wide/Normal width menu items. Both dimensions change independently; no locked aspect ratio. Persist only on gesture completion, never on every pointermove. Resize in place; uPlot setSize must track available content width and height without render()/reanalysis or losing zoom/cursors. Maximize uses the full available screen: card and content flex vertically, plot canvas grows in both dimensions, image canvas fills remaining area with timeline retained. Restore the exact prior size and viewport/camera. Avoid ResizeObserver loops. Card resize is opt-in at component level where tests lack onDimensions.

## Editor consistency

Replace Data/Axes/Appearance horizontal tabs with one vertically scrolling settings column and persistent preview beside it, plus sticky Cancel/Save actions. Clear section headings: Data, Axes, Appearance. Core controls (title/type/source selector; scales/bounds; smoothing/interpolation; basic line/point styling) are visible in predictable grouped rows, not buried in nested disclosures. Conditional controls depend only on relevance (image vs scalar, manual bounds, chosen style), not arbitrary hidden tabs. Advanced rarely-used details may use one consistent labeled disclosure per section, not deeply nested or mixed navigation systems. Keep actual plot types Line/Scatter/Area/Step; interpolation is separate. Source list has bounded search/paging; many individual series can use a consistent select/list, without forcing the whole form to grow unbounded. Preserve transactional save/cancel/errors/focus, live full-history preview, keyboard access and 390px layout. Worker updates its own fixtures; parent adapts other integration scripts that previously clicked tabs.

## Stable image transitions

Remove per-frame Loading frame text entirely. Frame changes must not add/remove a status row that shifts controls. Keep old decoded frame visible until replacement is ready, then swap atomically while preserving camera. Abort/stale requests must not flash old/new images out of order. Do not clear the viewer between successful frame changes. Actual errors may use a reserved/overlay area without changing canvas or timeline geometry; initial/empty states may be explicit but must not jump on every scrub. Parent cards changes own flexible dimensions; image worker must avoid hardcoding new card aspect ratios.

## Acceptance evidence

Use source fixtures plus actual embedded-server journeys. Check a 50+ run drawer and dense table, first-content y position, viewport/canvas utilization under maximize, pointer resize width/height/reload/cancel, zoom tolerance geometry and blue selection pixels, cursor/numerical invariance, hidden default legends/shared colors, long-name readout overflow, one-scroll editor consistency and delayed-frame layout/pixel stability. Capture representative desktop/narrow/maximized/editor images; distinguish decoded pixel/computed-layout inspection from visual image access. Preserve existing backend/security/numerical regressions.

## Latest feedback: authoritative interaction additions

Default left drag zooms; right-button drag or Space+left-drag pans. Set PlotInteraction.directGestures=true on cards. Native context menu is suppressed on the plot when handling right pan, not globally. No Pan/Zoom/Inspect/Threshold word-button mode row. Keep small accessible icon controls with tooltips for zoom in/out, fit/back and cursor creation. Cursor creation can temporarily arm placement; after placing return to ordinary zoom, while proximity dragging existing cursor lines remains available. Navigation owns cursor hit testing and temporary gesture suppression, cards own controls/readouts. Hide native hover crosshairs and hover markers throughout panning, clear stale hover readout, and avoid resurrecting stale coordinates at release; user-pinned comparison lines stay tied to data coordinates.

Backward-compatible horizontal cursor contract: plot.ts Pins and navigation.ts local Pins gain optional yA/yB:number|null. Existing a/b are vertical, threshold is legacy only. PlotInteraction.cursorAxis?:'x'|'y' and onHorizontalPin?:(pin:'a'|'b',value:number)=>void are shared. Navigation calls putPin('yA'|'yB',value) and onHorizontalPin for horizontal comparisons, retains onPin for a/b/threshold. Cards set cursorAxis when arming creation; nav directly drags existing x/y pins in directGestures zoom mode. Navigation worker may use its own local extended Pins; cards worker owns plot.ts compatibility changes. Horizontal inspector shows A/B levels, delta Y and each run's full crossing-step results including multiple crossings/plateaus; no silently selected first crossing. Cursor labels must be offset with opaque backing, clamped inside edges and avoid overlap when A/B coincide or are close. Test label geometry as well as plotted values.

## Run detail and editable colors

Dedicated run page replaces popup: shell routes #/experiments/:experimentId/runs/:runId and calls run-detail.ts export renderRunDetail(run:Run, options:{onBack:()=>void;onCharts:()=>void}):HTMLElement. Detail worker owns NEW run-detail.ts, run-detail.css, run-config.ts and their tests ONLY; shell integrates import/routing and stops using showRunDetails. Run detail has compact identity/status/timestamps, convenient parameter browsing with search by path/value, expandable dotted-key AND nested-object namespaces, accurate typed values including arrays/null/booleans, collision-safe leaf/group handling, full copyable paths/values, and readable long paths. Tags separate. No YAML upload backend claimed: existing params represent parsed configuration, preserve exact data; offer JSON copy/export without adding parser dependencies unnecessarily.

Run colors are shared across run table, drawer and plots. Parent owns series-colors.ts and NEW run-color-picker.ts helper. Public API runColor(catalog,runId), setRunColor(runId,color:string|null):boolean (local persisted override, null resets; false on storage error), withRunColors(config,sources,catalog), runColorButton(catalog,runId):HTMLElement. Successful assignment emits window event 'nset:run-colors-changed'; shell rerenders swatches and refreshes display colors of existing cards without refetching histories or resetting navigation; cards expose refreshColors():void; editor listens while open and refreshes preview display only. User explicit chart series overrides/single-color mode remain authoritative. Helpers provided by parent after worker start; use imports as contract, do not implement competing persistence. Shell owns run table color buttons. Detail worker may use runColorButton beside run name. Local browser scope is explicit, no server-wide saved preference claim.

Worker ownership clarification: shell owns browser-tables.ts plus integration of run-detail only; run-detail worker does not touch main.ts. Parent will adapt shared state and cross-component tests. All workers implement then commit owned files, test via Pixi/rx with isolated browser ports, and return commit/evidence/known integration needs.
