# Image inspection workflow

The task is to follow a small feature through training snapshots without losing its location or mistaking which observation is displayed. The baseline already keeps decoded frames and their matching captions visible while the next frame loads. This pass preserves that behavior and chooses changes that add no controls or occupied screen space.

At baseline `4049746`, one off-center Alt-wheel gesture displaced the point being inspected by 65.28px in the desktop fixture and 39.25px in the narrow fixture. A pointer-anchored runtime prototype reduced that to approximately zero and 0.22px, including rotated and flipped cases. The audit also reproduced a source-identity error: changing the image key cleared the pixels but left the previous key's step, frame count and tooltip visible until new bytes arrived. These are interaction and truthfulness defects, not aesthetic judgments.

The selected implementation scope is pointer-anchored image zoom plus source-only frame-metadata cleanup. The latter uses the existing neutral metadata slot when the viewer resets; it must not restore a loading-frame banner or discard the last valid frame during ordinary same-stream scrubbing. Frame decoding, authenticated original image bytes, cache bounds and latest-request cancellation remain unchanged.

A numeric nearest-step prototype was also compared. For the scripted traversal of irregular steps it reduced seven frame-selection commits to one, but a user who already knows the ordinal can move the existing slider in one action. The prototype also added 26px to the narrow card's toolbar. That is insufficient evidence to add a permanent input; step entry is deferred pending a design that does not consume another row and makes missing steps and ties explicit.

The primary comparisons are the pinned W&B media-panel documentation at revision `86eefc342c347f15ce6a4cda3114e9daeaccd403` and MLflow image-slider source at `1795b4d7cf870078174a90fe955fab8cf5317cd2`. W&B separates media keys from the step slider; MLflow builds marks from actual logged steps and separates temporary slider motion from committed selection. These support clear source/step semantics, not an assertion that either product uses the chosen zoom implementation. The reference image bundle r209 and OCR r210 retain the media illustration, provenance and recognized label positions outside the shipped app.

Audit r208→r215 passed 12 scenarios and retained 31 PNGs plus four JSON measurement files in `../.rx-worktrees/r215/web/test-results/`. The comparison used identical 1024×512 native PNGs, 600/358px hosts and 1440/390px viewports. Geometry, pointer displacement, camera state, source metadata and decoded pixels were inspected. The image tool did not expose viewable pixels to the model, so this is not a claim of direct visual aesthetic assessment. Production implementation and integrated release verification are recorded separately when complete.
