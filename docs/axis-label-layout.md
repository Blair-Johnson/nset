# Axis-label safety follow-up

The r190 density comparison exposed two presentation defects rather than a reason to shrink every gutter: billion-scale Y ticks overlapped the vertical title, and full timestamp text clipped at the right edge. Commit `224ef90` changes default tick presentation only. Numeric Y ticks choose the shorter existing six-significant-digit spelling or an equivalent exponential spelling, such as `3e9`; coordinate readouts and numerical values are unchanged.

Default linear wall-time ticks keep the complete UTC date, time, millisecond precision when present, and UTC suffix, using two native uPlot lines aligned to the tick. Their fixed allocation grows from 32 to 44 pixels. On the tested small card, the drawable height falls from 139 to 127 pixels at mobile width and from 131 to 119 at desktop width. This is a 12-pixel cost for readable labels, not a density improvement. The competing fixed-reserve alternative consumed 90 pixels of timestamp plot width and reduced mobile tick count. No fonts were shrunk, titles removed, or adaptive gutters introduced.

Explicit axis formatting, layout and padding remain user-controlled. Whole-millisecond default tick increments on linear time axes avoid duplicate UTC Date labels; a sub-millisecond viewport may have no whole-millisecond tick, while explicit numeric formatting remains available. Independent review found that nonlinear axes generate splits separately from this increment list. They conservatively retain legacy formatting rather than receiving an unsupported whole-millisecond guarantee; regressions cover log and inverse-hyperbolic time axes. The measured fixture matrix does not establish universal safety for arbitrary fonts, custom multiline labels, axis sizes or extreme numeric strings. A deliberately undersized custom top-axis case clipped identically before and after; the implementation does not silently rewrite that padding.

Worker acceptance r202 passed 284 unit tests, the production build and 80 browser scenarios. Its 1,004 measured states included 728 production states and 2,912 production cursor badges, with no measured text clipping, overlaps, badge collisions or escapes in the production cases. The cases cover two viewport widths, DPR1/2, repeated zoom/pan/resize, representative maximize/restore, reversed scales, negative and large numbers, millisecond timestamps, and custom overrides. PNGs and transformed canvas text bounds are retained under `../.rx-worktrees/r202/web/test-results/`; no direct visual-inspection claim is made.

Normal regression runs retain all measurements and assertions, representative card screenshots, and screenshots of detected clipping/collisions. Set `NSET_AXIS_CAPTURE=all` to regenerate every state image. The full integrated acceptance result will be recorded after parent review and verification; the deployed workflow-polish release remains unchanged until then.
